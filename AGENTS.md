# Правила проекта

Основа: [project-starter-rules](https://github.com/f1nando/project-starter-rules).

- Приоритет: быстро получить работающий результат, сохраняя простоту и приемлемую надёжность.
- Единственная постоянная база данных — MongoDB. SQL и SQL-инструменты не добавлять.
- Архитектура по умолчанию — модульный монолит без преждевременной инфраструктуры.
- Frontend должен собираться независимо и поддерживать fixtures для разработки без backend.
- Весь публичный пользовательский интерфейс вне админки, включая статусы, ошибки, подсказки и accessibility-тексты, должен быть только на английском языке. Язык админки выбирается по текущим требованиям пользователя и не ограничивается этим правилом.
- Проверки должны быть focused и соответствовать затронутой области. Полный suite запускается отдельно перед релизом.
- Внешние запросы имеют timeout, ограниченные retries и явную обработку ошибок.
- Денежные операции должны быть идемпотентны; неизвестный результат нельзя повторять вслепую.
- Секреты хранятся только вне Git через environment или внешний credentials-файл и не попадают в логи.
- Каждая завершённая логическая правка получает отдельный локальный commit после просмотра diff и короткой проверки.
- Push, PR, release и deployment выполняются только по прямой просьбе пользователя.
- Не трогать чужие изменения и не использовать destructive Git-команды.
- При локальной разработке должен работать только один экземпляр dev-стека проекта. Перед `npm run dev` проверить процессы/порты `3001` и `5173`; при перезапуске сначала остановить существующий watchdog со всем его деревом процессов и только затем запустить один новый стек. Не запускать параллельно `dev`, `dev:stack`, `dev:api` или `dev:web`.

## Работа с моделями и субагентами

- Основной оркестратор проекта — `openai/gpt-5.6-sol`. Он декомпозирует задачи, принимает архитектурные и денежные решения, интегрирует изменения, проверяет фактический diff, запускает проверки и создаёт локальные коммиты.
- Субагенты используются только когда параллельное исследование, независимое ревью или изолированная реализация действительно ускоряют работу. Простые локальные правки выполняет оркестратор без делегирования.
- Для обычных субагентных задач приоритет имеют модели OpenCode Go с месячной квотой `$60`:
  - `opencode-go/kimi-k2.7-code` — изолированная реализация и тесты;
  - `opencode-go/mimo-v2.5` — быстрый поиск и исследование;
  - `opencode-go/qwen3.7-plus` и `opencode-go/qwen3.6-plus` — анализ и документация;
  - `opencode-go/minimax-m3` — тестовые сценарии и независимое ревью;
  - `opencode-go/qwen3.7-max` — более сложное ревью, когда дешёвых моделей недостаточно.
- Модели с месячной квотой `$15`, включая GPT-5.6 Luna, Kimi K3, DeepSeek V4 Pro, Qwen3.8 Max и MiMo V2.5 Pro, использовать только если модели из пула `$60` не справились или нужен особенно сильный независимый взгляд.
- Квоты и каталог OpenCode Go могут меняться. Перед явным выбором модели проверять её доступность и актуальную квоту; неизвестную модель не считать частью пула `$60` без подтверждения.
- Обычно запускать не более 2–3 независимых субагентов одновременно. Параллелить только задачи без пересечения по изменяемым файлам.
- `explore` используется для чтения, поиска и отчётов; `general` — для ограниченной реализации. Один файл не должен параллельно редактироваться несколькими агентами.
- Вывод субагента не считается доказательством: оркестратор перечитывает изменённые файлы, проверяет официальные источники для внешних API, запускает focused tests и просматривает diff.
- Формулы PnL, risk engine, идемпотентность, размещение ордеров, работа с секретами и другие денежно-критичные решения всегда остаются под контролем оркестратора и по возможности получают независимое ревью.
